# v2.0 Deployment Guide

## Prerequisites

- RHEL 9 / CentOS Stream 9
- Python 3.11 or newer
- `bw` CLI installed at `/usr/local/bin/bw`
- `vault_unlock.sh` installed at `/usr/local/bin/vault_unlock.sh`
- SSH access to NIRD configured (see SSH config section below)

---

## 1. Bitwarden Setup

### 1.1 First-time initialisation (run once as the seqtech user)

Log in and register the device:

```
/usr/local/bin/bw login
```

Follow the CLI prompts to complete login and device registration.

The Bitwarden master password must not be the same as the domain password.

### 1.2 Install the bw-serve systemd service

Copy the unit file into the user systemd directory:

```
cp systemd/bw-serve.service ~/.config/systemd/user/bw-serve.service
```

Edit `ReadWritePaths` in the unit file to match the seqtech user's home directory:

```
ReadWritePaths="/home/<seqtech_user>/.config/Bitwarden CLI"
```

Enable and start:

```
systemctl --user daemon-reload
systemctl --user enable --now bw-serve.service
loginctl enable-linger $USER
```

### 1.3 Unlock the vault

Before any pipeline run the vault must be unlocked manually:

```
/usr/local/bin/vault_unlock.sh
```

The user will be prompted for their Bitwarden master password. The vault must be
unlocked after every reboot. If the host reboots, `bw-serve.service` will send an
email to the operator reminding them to unlock.

---

## 2. SSH Config for seqtech User

The pipeline resolves all SSH connection parameters exclusively from `~/.ssh/config`.
No inline hostnames, users, or ports are permitted.

The seqtech user's `~/.ssh/config` must contain entries for every hop in the NIRD
ProxyJump chain with the following required fields:

```
Host <alias>
    HostName        <fqdn or ip>
    User            <username>
    IdentityFile    ~/.ssh/<keyfile>
    IdentitiesOnly  yes
    StrictHostKeyChecking yes
    VerifyHostKeyDNS yes
    UserKnownHostsFile ~/.ssh/known_hosts
```

For NIRD (keyboard-interactive 2FA), omit `IdentityFile` - the pipeline detects
the absence of an identity file and switches to TOTP authentication automatically.

Host keys for all hops must be present in `~/.ssh/known_hosts` before the first
run. The pipeline uses strict host key checking and will refuse to connect to any
host not already in `known_hosts`.

Add host keys manually:

```
ssh-keyscan <hostname> >> ~/.ssh/known_hosts
```

Verify before running the pipeline.

---

## 3. Service Account for Cathrine on Bitwarden

The Bitwarden service account must contain the following items:

- NIRD login credentials (username, password, TOTP secret)
- SSH key passphrase for the seqtech user's identity file (if key is encrypted)

Items must be stored using the hostname as the lookup key. The pipeline fetches
credentials by hostname via the Bitwarden local API at `http://127.0.0.1:8087`.

Credentials are never written to disk.

---

## 4. Install and Enable the Demux Service

Copy the unit files into the user systemd directory:

```
cp systemd/demux.service ~/.config/systemd/user/demux.service
cp systemd/demux.timer   ~/.config/systemd/user/demux.timer
```

Reload, enable, and start:

```
systemctl --user daemon-reload
systemctl --user enable --now demux.timer
loginctl enable-linger $USER
```

The timer fires every 20 minutes (minute 0, 20, 40). The service is `oneshot` -
it runs, completes, and exits. The lock file at `$XDG_RUNTIME_DIR/demux/demux.lock`
prevents overlapping runs.

Verify the timer is active:

```
systemctl --user list-timers demux.timer
```

Verify the service runs without errors:

```
systemctl --user start demux.service
journalctl --user -u demux.service -f
```

## 5. Post-deployment Verification

- [ ] `bw-serve.service` is running: `systemctl --user status bw-serve.service`
- [ ] Vault is unlocked: `curl -s http://127.0.0.1:8087/status | python3 -m json.tool`
- [ ] SSH connectivity to NIRD: run pipeline manually with a known good RunID
- [ ] `demux.timer` is active: `systemctl --user list-timers`
- [ ] Linger is enabled: `loginctl show-user $USER | grep Linger`
